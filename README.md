# HostelDesk

HostelDesk is a proposed hostel-management system that brings common student, hostel-staff, mess-staff, and external-user interactions into one organized place. Over the next month, our team will turn the project idea into a clearly scoped, designed, and testable first version.

## Project users

- **Students** — access hostel information and submit or follow up on common requests.
- **Hostel staff** — manage hostel operations and student requests according to staff roles and hierarchy.
- **Mess staff** — coordinate mess-related information and tasks according to staff roles and hierarchy.
- **External users** — use the information or processes intended for people outside the hostel community.

The exact permissions and workflows for each role will be confirmed during requirements gathering.

## Plan for the next month

### Week 1 — Understand and define

- Discuss the project idea with the team and identify the main problems HostelDesk should solve.
- Gather requirements from the four user groups and map their important workflows.
- Agree on the first version's scope, user roles, and priorities.
- Write user stories and acceptance criteria; record open questions and assumptions.

**Deliverable:** an agreed requirements and scope document, with a prioritized feature list.

### Week 2 — Design the solution

- Sketch the main user journeys and create initial wireframes for the key screens.
- Define role-based access needs, core data, and how the major parts of the system fit together.
- Review the designs and workflows as a team and update them based on feedback.
- Choose and document the implementation tools and divide the work into manageable tasks.

**Deliverable:** reviewed wireframes, a basic system design, and an implementation backlog.

### Week 3 — Build the first working version

- Set up the project structure and shared development workflow.
- Implement the highest-priority end-to-end workflow agreed in Week 1.
- Add the relevant screens, data handling, and role checks for that workflow.
- Integrate team contributions regularly and track issues in version control.

**Deliverable:** an early working prototype of the agreed core workflow.

### Week 4 — Test, refine, and present

- Test the prototype against the user stories and acceptance criteria.
- Fix the most important usability and functional issues.
- Ask representative users or classmates for feedback where possible.
- Prepare a short demo and document completed work, known limitations, and next steps.

**Deliverable:** a tested prototype, demo, and prioritized follow-up list.

## How we will work

- Keep the first version focused; finalize specific features after the Week 1 requirements discussion.
- Assign an owner and clear acceptance criteria to each task.
- Use version control, small changes, and regular integration to avoid last-minute conflicts.
- Review progress at least weekly and update priorities when new information emerges.
- Test key workflows as they are implemented, rather than leaving all testing until the end.

## Initial measures of progress

By the end of the month, we aim to have:

- documented and prioritized requirements for the main user groups;
- reviewed user journeys and initial interface designs;
- a working prototype demonstrating at least one agreed end-to-end workflow;
- test results, known limitations, and a clear plan for what to build next.

*This is an initial plan. The team will refine the scope and milestones after confirming requirements and reviewing the project proposal.*
